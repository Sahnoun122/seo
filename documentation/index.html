SEO Gen AI

Welcome to the official documentation for SEO Gen AI — a complete, production-ready SaaS web application that turns a single keyword into a fully structured, SEO-optimised article in seconds using AI. Built with React 19 + Vite on the frontend and Node.js / Express 5 on the backend.

Ready to sell on CodeCanyon & CodeSter

Full backend + frontend, tests, CI/CD, Swagger API docs, GDPR legal pages, i18n (6 languages), Stripe payments, and AWS S3 image storage — all included.

SSE Streaming Generation

One-Click Auto Install

The included install.sh bash script checks prerequisites, copies .env templates, and installs all dependencies automatically.

Prerequisites

Node.js v20+ and npm v9+ must be installed. MongoDB must be running locally or accessible via Atlas URI.

Step 1

Run the installer

Terminal — project root
bash install.sh

The script copies .env.example → .env for both frontend and backend, then runs npm install in all three directories.

Step 2

Configure secrets

Open backend/.env and fill in at minimum:

  • MONGODB_URI — your MongoDB connection string
  • JWT_SECRET — generate a 64-char random string
  • ENCRYPTION_KEY — must be exactly 32 characters
  • OPENAI_API_KEY — or leave blank and add it later in Settings

See the Environment Variables tab for full descriptions of every variable.

Step 3

Start both servers

Terminal
npm run dev

Frontend → http://localhost:5173  |  Backend API → http://localhost:5000/api  |  API Docs → http://localhost:5000/api/docs

Step-by-step instructions for configuring and starting each component independently.

3. Install & start the frontend

4. Verify the API docs

Open http://localhost:5000/api/docs in your browser. You should see the interactive Swagger UI with all endpoints documented.

5. Create your admin account

  2. If you need to promote an existing user to admin manually, run this in your MongoDB shell or Compass:
MongoDB Shell

)

Features Guide

A walkthrough of every user-facing feature in the platform.

Article Generation

Dashboard
  1. Type your target keyword (up to 100 characters) into the generation input on the Dashboard.
  2. Click Generate Article. The button switches to a live progress indicator.
  3. Content streams word-by-word via Server-Sent Events (SSE) — you see each step label in real time: Writing article…, Generating keywords…, Finalising…
  4. The finished article appears as a card showing: Title, Meta Description, full Markdown content, and 5–10 suggested keywords in the sidebar panel.

Each generation consumes 1 credit. Users who add their own API key in Settings get unlimited generations.

Cover Images

Two ways to add a cover image to an article:

  • Manual upload — click the Add Cover button, pick a JPEG/PNG/WebP/GIF. The backend converts to WebP, generates 4 thumbnail sizes via Sharp, and stores on S3. A signed URL (1-hour expiry) is returned.
  • AI Cover (DALL-E 3) — click the AI Cover button (Sparkles icon). The backend sends the article title and keywords to DALL-E 3 (1792×1024, standard quality), downloads the generated image, and uploads it to S3. Result appears instantly in the article card.

AI Cover requires AWS S3

DALL-E returns a temporary URL (1-hour expiry). The app downloads the image and re-uploads it to your S3 bucket for permanent storage. Requires AWS_* variables to be configured.

Article History & Management

  • Search — filter your history by keyword or title using the search input.
  • Version History — every refinement creates a new version. Click the version clock icon to restore any previous version.
  • Refine — send a natural-language instruction to the AI to rewrite or improve sections of the article.
  • Delete — removes the article and its associated S3 images permanently.

Internal Linking Assistant

On any article, click the Internal Links panel in the sidebar. The assistant analyses your article content alongside your other published articles, and suggests contextually relevant internal links to insert. You can also provide a list of known URLs manually.

Stripe Payments

The platform supports two payment flows: monthly subscriptions (Starter, Growth, Pro) and one-time credit packs. Both are optional — omit the Stripe keys from backend/.env to disable payments entirely.

Use Test Mode first

Create a free account at stripe.com and work in Test mode before switching to live keys.

Step 1 — Create Products

Subscriptions

Go to Stripe Dashboard → Products → Add Product and create three subscription products:

  • Starter — $9/month — 20 credits/month
  • Growth — $29/month — 100 credits/month
  • Pro — $99/month — 500 credits/month

Each must use Recurring billing (monthly). Copy each Price ID (price_1ABC…).

Credit Packs

Create additional One-time products for credit purchases. Copy their Price IDs into frontend/src/pages/BuyCredits.jsx in the packages array and into backend/controllers/stripeController.js in CREDIT_PACKAGES.

Step 2 — Set Price IDs in frontend/.env

frontend/.env
VITE_STRIPE_PRICE_STARTER=price_1XXXXXXXXXXXXXXXXXXXXXXXXXX
VITE_STRIPE_PRICE_GROWTH=price_1YYYYYYYYYYYYYYYYYYYYYYYYYYYY
VITE_STRIPE_PRICE_PRO=price_1ZZZZZZZZZZZZZZZZZZZZZZZZZZZZ

Step 3 — Add Stripe keys to backend/.env

backend/.env
STRIPE_SECRET_KEY=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...

Step 4 — Configure Webhook (local dev)

Install the Stripe CLI and run:

Terminal
stripe listen --forward-to localhost:5000/api/stripe/webhook

Copy the printed whsec_… secret into STRIPE_WEBHOOK_SECRET in backend/.env.

Step 5 — Go Live

Switch Stripe to Live mode. Create matching live products with live Price IDs. Update STRIPE_SECRET_KEY to sk_live_… in your production environment. In Stripe Dashboard → Developers → Webhooks, add an endpoint pointing to https://your-api.yourdomain.com/api/stripe/webhook and paste the signing secret into production STRIPE_WEBHOOK_SECRET.

WordPress Integration

Users connect their WordPress site from Settings → Content Preferences. Generated articles can then be published as drafts with one click, including the cover image as the WordPress featured image.

Requirements

  • WordPress 5.6 or higher (Application Passwords are built-in)
  • The WordPress REST API must be reachable from the server (not blocked by a WAF or security plugin)

Step 1 — Generate an Application Password

WordPress Admin
  1. Log into WordPress Admin → Users → Profile.
  2. Scroll to the Application Passwords section.
  3. Enter a name (e.g. "SEO Gen AI") and click Add New Application Password.
  4. Copy the password — it is shown only once.

Application Passwords not visible?

Some security plugins (Wordfence, iThemes) or managed hosts disable Application Passwords. Check plugin settings or contact your host to enable the REST API.

Step 2 — Connect in Settings

SEO Gen AI Settings

Fill in three fields under WordPress Integration:

  • WordPress URL — site root, no trailing slash: https://myblog.com
  • Username — your WordPress login username (not email)
  • Application Password — from Step 1

The password is encrypted with AES-256 before being stored in MongoDB.

Step 3 — Publish an Article

From any article card, click the WordPress button. The app:

  • Converts Markdown to HTML blocks
  • Uploads the cover image to WordPress Media
  • Creates the post as a Draft with the cover as featured image
  • Stores the meta description in a _yoast_wpseo_metadesc custom field (Yoast-compatible)

Troubleshooting WordPress Errors

401 Unauthorized

Verify you entered the WordPress username (not email). Regenerate the Application Password. Ensure the user has at least Editor role.

REST API returns 404

Go to Settings → Permalinks in WordPress Admin and click Save Changes. This flushes rewrite rules and re-registers REST routes.

Deploy to Vercel

The project ships with a vercel.json in the backend/ folder that configures the Express server as a Vercel Serverless Function. The frontend is a standard Vite SPA.

Step 1 — MongoDB Atlas

Database
  1. Create a free cluster at cloud.mongodb.com.
  2. Create a database user (username + strong password).
  3. Under Network Access, add 0.0.0.0/0 to allow connections from Vercel's dynamic IPs.
  4. Click Connect → Connect your application and copy the connection string.
  5. Replace <password> in the string with your database user password.

Step 2 — Deploy the Backend

Vercel
  1. Create a new project in the Vercel dashboard. Set the Root Directory to backend.
  2. Under Environment Variables, add all variables from your backend/.env.
  3. Set NODE_ENV = production.
  4. Deploy. Note the deployment URL (e.g. https://seo-gen-ai-api.vercel.app).

Step 3 — Deploy the Frontend

Vercel
  1. Create another Vercel project. Set the Root Directory to frontend.
  2. Add environment variables:
    • VITE_API_URL = https://seo-gen-ai-api.vercel.app/api
    • VITE_STRIPE_PRICE_* = your live Stripe Price IDs
  3. Deploy. Note the frontend URL.

Step 4 — Wire CORS

In the backend Vercel project, update the CLIENT_URL environment variable to your frontend Vercel URL (e.g. https://seo-gen-ai.vercel.app). Redeploy the backend.

Step 5 — Production Stripe Webhook

In the Stripe Dashboard → Developers → Webhooks, add a new endpoint:

  • URL: https://seo-gen-ai-api.vercel.app/api/stripe/webhook
  • Events to listen for: checkout.session.completed, invoice.payment_succeeded, customer.subscription.deleted

Reveal the Signing secret and update STRIPE_WEBHOOK_SECRET in the backend Vercel project environment variables.

Vercel Serverless Function Limits

Vercel's Hobby plan has a 10-second function timeout. SSE streaming requires the Pro plan (no timeout limit). Consider Render, Railway, or Fly.io for full server deployments.

Data Security Measures

  • Passwords hashed with bcrypt (cost factor 10) — never stored in plaintext.
  • API keys and WordPress credentials encrypted with AES-256 before DB storage.
  • All traffic encrypted in transit via HTTPS/TLS.
  • JWTs expire after 30 days; revoked on account deletion.
  • Rate limiting prevents brute-force attacks on auth endpoints.
  • HTTP security headers enforced via Helmet.js.
  • S3 images served via signed URLs (1-hour expiry) — not publicly accessible.
  • Zod input validation on all API endpoints — rejects malformed or malicious payloads.

Troubleshooting

MongoDB Connection Failure

MongooseServerSelectionError

Local: Start MongoDB — brew services start mongodb-community (macOS) or sudo systemctl start mongod (Linux).
Atlas: Go to Network Access and add 0.0.0.0/0 to the IP whitelist. Check you replaced <password> in the Atlas URI.

ENCRYPTION_KEY Error on Startup

SECURITY ERROR: ENCRYPTION_KEY must be at least 32 characters

The server will refuse to start in production if ENCRYPTION_KEY is shorter than 32 characters. Generate a valid key: node -e "console.log(require('crypto').randomBytes(16).toString('hex'))" — this outputs exactly 32 hex characters.

OpenAI / AI Generation Errors

402 / 429 — Quota exceeded

Your OpenAI account has no billing method or has hit its rate limit. Add a payment method at platform.openai.com/billing. Alternatively, switch to OpenRouter free models by setting OPENAI_BASE_URL=https://openrouter.ai/api/v1 and OPENAI_MODEL=meta-llama/llama-3.1-8b-instruct:free.

CORS Policy Blocked

Access blocked by CORS policy

Ensure CLIENT_URL in backend/.env matches your frontend origin exactly (protocol + hostname + port). In production, set it to your Vercel frontend URL. No trailing slash.

Swagger UI Blocked by CSP

Swagger UI blank / scripts blocked

Helmet enforces strict CSP by default. The server.js applies a relaxed CSP ('unsafe-inline') specifically for the /api/docs route before Swagger UI middleware. If you add custom middleware that overrides this, ensure the route-specific header is preserved.

Vercel Deployment: Function Timeout

Streaming times out on Vercel Hobby plan

Vercel Hobby limits serverless functions to 10 seconds. SSE streaming for long articles can exceed this. Upgrade to Vercel Pro (no timeout) or host the backend on Render / Railway / Fly.io with a persistent server.

Tests Failing: Cannot find module

Jest ESM resolution error

Ensure you run npm test from inside the backend/ directory. The test runner requires NODE_OPTIONS=--experimental-vm-modules (already set in package.json scripts). Node.js 20+ is required — check with node -v.
